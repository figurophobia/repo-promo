# Writing rules for promo posts

## Tell list: this is what makes text read as AI-written
- Em dash (`—`) mid-sentence or as an opener ("Hey —").
- Openers: "Hey", "So,", "Basically,".
- Bold everywhere, and perfect bullet lists with ":" on every line.
- Phrases: "Curious:", "Happy to answer questions", "Would love to see what you make",
  "not just X, it's Y", "from A to B", triple adjectives ("fast, clean and simple").
- Decorative emojis (a single ⭐ is fine).
- An over-polished closing question.

The fix: short sentences, contractions, a bit of imperfection, talk like you're explaining it
to a coworker. Less decoration, more concrete detail.

## The AI rule
**Only `r/vibecoding` gets a mention of AI.** Their rules require posts about your projects to
include the tools and process used. Everywhere else: not a word about AI.

## Structure that works (from the user's own best posts)
1. Title = the problem or the concrete novelty. **Never** start it with "GitHub:" and never
   use the repo slug. Bad: `GitHub - user/repo: unofficial client`. Good: `I got tired of X so
   I built Y`.
2. First line: one line of context (what you did before and why it annoyed you).
3. What you built, with the honest concrete detail that makes it credible (time spent, what
   broke, what doesn't work yet).
4. A short "what it does" list, verbs not jargon.
5. Links: demo/repo. Source link + "star if you like it" is fine.
6. Close with a normal question or a plain invitation, not a polished one.

## Template

Title options:
```
I built <thing> because <concrete pain>
I spent <time> making <tool> so you don't have to <chore>
<tool> does <X> in <Y>
```

Body:
```
<One line of context, no "Hey".>

<What you built and why, with the concrete detail.>

What it does:
- <feature 1>
- <feature 2>
- <feature 3>

Try it: <link>
Source: <link github>

<A normal closing question or invitation.>
```

## r/vibecoding variant (only here mention AI)
Must include: tools used, the workflow/loop, and insights or things that broke. Put the repo
link in the first comment, not the body. Dev tools also need mod approval beforehand (via
their X community).
